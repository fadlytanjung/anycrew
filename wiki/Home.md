# anycrew wiki

This wiki explains every term and concept anycrew uses, one page each, with how anycrew applies it
and an example. Start with the glossary if you want one-line definitions, or follow the reading
order below.

## Reading order

1. [Spec-Driven Development](Spec-Driven-Development.md): the method everything else serves
2. [Lifecycle and Phases](Lifecycle-and-Phases.md): discover → define → design → specify → build → verify → ship → record
3. [Constitution](Constitution.md): the principles every change is checked against
4. [Product Requirements Document](Product-Requirements-Document.md) and [Acceptance Criteria](Acceptance-Criteria.md)
5. [Architecture Decision Record](Architecture-Decision-Record.md)
6. [Spec, Plan and Tasks](Spec-Plan-Tasks.md): the feature loop
7. [Implementation Status](Implementation-Status.md): the one doc that says what is built
8. [Agents, Skills and Rules](Agents-Skills-Rules.md): the three kinds of customisation
9. [Model Tiers](Model-Tiers.md): fast, balanced, strong
10. [Gates and Human-in-the-Loop](Gates-and-Human-in-the-Loop.md)
11. [Patterns and Quality](Patterns-and-Quality.md): architecture styles, design patterns, code smells
12. [Hooks](Hooks.md), [Presets](Presets.md), [Standards](Standards.md)
13. [Glossary](Glossary.md) and [FAQ](FAQ.md)
